## P1 — Data loss, wrong results, logic bugs

### Data and saving
- [ ] **[L] Non-atomic save, no backup** — `model/json_model.py:79` → `errors.safe_json_save`. Opens the source-of-truth JSON in `'w'` mode (truncates it) and writes. A failure midway (disk full, kill) leaves a broken file. Write to `*.tmp` + `os.replace`, and keep a `.bak` of the previous version.
- [ ] **[V] `safe_json_save` fails for paths without a directory** — `errors.py:187`: `os.makedirs(os.path.dirname('x.json'))` → `os.makedirs('')` → `FileNotFoundError`. Returns `False` and the model raises "Failed to save". Reproduced with `safe_json_save('rel_test.json', {})`.
- [ ] **[V] JSON files with a BOM do not load, although the comment says they do** — `model/json_model.py:65` ("utf-8-sig automatically strips BOM") but `safe_json_load` opens with `encoding='utf-8'`. Reproduced: "Unexpected UTF-8 BOM". Use `utf-8-sig`.
- [ ] **[L] JSON formatting is lost on save** — `json.dump(..., ensure_ascii=False, indent=2)`. If the original JSON (generated by `make rip`) uses a different format, the first save rewrites the whole file and the git diff is huge. Check against the real JSON and, if it differs, match `indent`/separators/trailing newline.
- [ ] **[L] `set_entry` marks things dirty even when nothing changes** — `model/json_model.py:127`. An out-of-range index is silently ignored but still does `dirty_keys.add`, sets `isDirty=True` and emits `section_changed`. A negative index does write (Python negative indexing). Validate `0 <= idx < len`, and don't mark dirty if the text is identical.
- [ ] **[L] `isDirty` is set in the JSON but never cleared** — `json_model.py:149`. After saving and building, `encode-ff4.js` will keep re-encoding those sections. Confirm whether this is intentional (probably consumed by the encoder) and document it.
- [ ] **[V] `json_to_display`/`display_to_json` are not inverses** — `util/text_processing.py:194-229`. Over 18,365 strings in the EN JSON there is 1 case: `...there.\n \line There...` (mapDialog #65) loses the space between `\n` and `\line` (the `buf` buffer is discarded when `\line` arrives). Any edit to that entry changes bytes without the user noticing. Add a round-trip test over the whole JSON (see Tests).
- [ ] **[L] `revert_char_names` is ambiguous when two characters share a name** — `text_processing.py:184`. `{Name}` → `\charNN` uses a `name→idx` dict; with repeated names the last one wins. `display_to_json` applies it to the **whole** text on every commit, so an untouched `\char03` can be rewritten as another code. There are no duplicates in the EN JSON (verified), but ES/JP may have them, or they may appear after renaming. Preserve the original mapping (e.g. don't convert when the name is ambiguous).

### Capacities / byte budget (bar and 🔴🟡 dots)
- [ ] **[V] Capacities from the `.lnk` are whole-bank sizes, not segment sizes** — `model/linker.py:68-95`. For `ff4-en.lnk` it returns `eventDialog1: 65536` and `eventDialog2/battleDialog/battleMessage/itemDescription/mapTitle: 32768`. `item_desc` shares bank `0f` with many segments and its real room is about `$200` bytes: the bar shows ~1 % when it may actually be overflowing. Compute capacity as the distance to the next segment (or the segment's own `size` when it has `start`), not the size of the MEMORY area.
- [ ] **[V] `_SEGMENT_TO_KEY` does not match the real `.lnk` segment names** — `linker.py:13-30`. It maps `attack_names`, `item_names`, `char_names`, `class_names`, `monster_names`, `spell_names`, `status_names`, `battle_cmd`, but the `.lnk` uses `attack_name`, `char_name`, `status_name`, etc. (per your `ff4-es.map`). Those sections never get a capacity from the `.lnk` and fall back to the JSON `range`. `event_dlg3` is also missing.
- [ ] **[V] Off-by-one in the JSON `range` fallback** — `model/json_model.py:210`: `e - s` with inclusive ranges (`0x0F8000-0x0F88FF`) gives 2303 when it is 2304 bytes. Add 1.
- [ ] **[L] The `.lnk` regexes are brittle** — `linker.py:72-92`. They require `load = X, type = ro` adjacent (fails with `load=…, start=…, type=ro`), don't skip `#` comments (a commented-out line gets parsed), and expect `start=…,size=…` in that order. Use a line-based parser that strips comments and reads key=value pairs.
- [ ] **[L] `eventDialog3` is inconsistent** — `constants.py`: it is in `VWF_SECTIONS` but not in `TEXT_SECTIONS` or `DIALOG_SECTIONS`, so on ES (whose map has `event_dlg3`) it does not appear in the sidebar. If it were shown, `is_dlg` would be false and it would be edited as a name card.
- [ ] **[L] `used_bytes` for `mapDialog` is approximate** — `json_model.py:160-185` (the comment says so). And `encode_size` in `model/encoding.py` has not been checked against the real encoder (`romtools/rom-encoder`). Its `CTRL_PAT` regex tries `\n` as an alternative before `\w+`, and any token containing the substring `char` costs 2 bytes (e.g. `\charge`). Validate byte-for-byte against the repo's encoder.
- [ ] **[L] `entry_byte_cost`, `_commit` and `encode_size` duplicate logic**: `card_editor._commit` calls `encode_size` directly instead of `model.entry_byte_cost`.

### Reflow / text
- [ ] **[V] Syllable hyphenation ignores `measure` and overflows in VWF mode** — `util/text_processing.py:37-54` (`_hyphen_break`): it compares `len(left)+1 <= space_left` in characters, but in VWF `limit` is in pixels (224). Tested with `auto_hyphenate=True` and the real font: lines of **218, 303 and 98 px** with a 224 limit. Use `measure(left + '-')`.
- [ ] **[V] `reflow_text` ignores `hyphenate`/`measure` and silently truncates lines** — `text_processing.py:318-332`: it calls `reflow_line(line, limit)` without a measure, and `line_limit` drops the extra lines (tested: 10 lines → 2). It is imported in `card_editor.py` but unused; `_reflow_overlay` also truncates to `line_limit` (`card_editor.py:204`), **deleting text the user just typed**. Warn or mark in red, don't delete.
- [ ] **[L] After splitting a word, `rest` can still exceed `limit`** and the line stays too long (`reflow_line`, hyphenate branch).
- [ ] **[L] `TOKEN_PAT` glues punctuation to tokens** — `[^ ]+` captures `hola\char03,` or `{Cecil},` depending on alternative order, and the comma can end up alone at the start of the next line.
- [ ] **[L] Three different definitions of "control code"** (`text_processing.CTRL_PAT`, `encoding.CTRL_PAT`, `_SEG_PAT`/`_CMD`/`vwf_font.measure`: `\\[a-zA-Z0-9]+…` vs `\\\w+…`). Unify in one module.

### Editing in the overlay
- [ ] **[V] Highlighters accumulate** — `widgets/card_editor.py:82` creates a new `FF4Highlighter` on every `activate()` on the **same** `QTextDocument`; `self._hl = None` does not destroy it (its parent is the document). After 6 activations there were 7 highlighters (13 after another 6 in a different section). - [ ] **[L] No unsaved-changes prompt when opening another JSON** — `_on_open`/`_load_file` replace the model without asking.
- [ ] **[L] `QUndoStack` doesn't use `setClean()`** after saving, so it can't tell when the state returns to the saved one.
- [ ] **[L] `item._section_key = key`** (`ui_mainwindow.py:436`): a Python attribute attached to a `QListWidgetItem`; it can be lost if the wrapper is recreated. Use `item.setData(Qt.UserRole, key)`.

## P2 — Design and bad practices

- [ ] **Coupling through private attributes**: `CardEditor` and `VWFPainter` read `canvas._active/_cards/_vwf/_vwf_mode/_s/_text_area_rect/_vwf_qfont`; `ui_mainwindow` touches `config_mgr._section_overrides` (line 662), `_model._data`, and `main.py` calls `win._load_file`; `card_layout` reads `config._mono_font`; `json_model` imports the private `_lnk_path_for_json`/`_parse_lnk`. Expose a public API (signals + methods).
- [ ] **Dead "backward compat" layer in `CardCanvas`**: `_card_w`, `_card_h`, `_ncols`, `_total_height`, `_card_rect*`, `_overlay`, `_line_h`, `_vwf_qfont` delegate to or duplicate `CardLayout`/`VWFPainter`. `_vwf_qfont` exists twice (`card_canvas`, `vwf_painter._get_vwf_qfont`) and `_line_h` three times (`card_canvas`, `card_layout`, `card_editor`). Keep one.
- [ ] **The same setting is declared in 4 places**: `config.EditorConfig`, `typed_config.EditorSettings`, `ConfigKey` + `_KEY_TYPES`, plus `ViewDialog`/`ThemeDialog`. A new field means touching all of them. Base everything on one `dataclass` and `fields()` (with range/UI metadata).
- [ ] **`typed_config` is over-engineered with dead code**: `EditorSettings.merge` (its logic `if other_val != getattr(self.__class__, f.name, None) or f.name not in {...}` makes no sense), `SectionOverride.merge`, `to_dict` with a no-op comment, `ConfigManager._apply_dict`, `section_overrides: dict = None` (use `field(default_factory=dict)`), `_section_overrides: dict = None` in a `@dataclass`.
- [ ] **`errors.py` is mostly unused code**: `safe_execute`, `handle_error`, `safe_open_image`, `validate_dir_exists`, `get_logger`, `FileSaveError`, `FontError`, `ErrorSeverity.CRITICAL`; `safe_json_load` wraps the same error twice ("Failed to load X: Failed to load X: …"). The exception hierarchy is oversized for what is used. Delete it or actually use it.
- [ ] **`logging.basicConfig` at import time in `errors.py`**: configure logging in `main.py`, not in a library module. There is a mix of `print()` (`ui_mainwindow.py:460` always prints `[section selected]`, without `--verbose`) and the logger.
- [ ] **Mutable global state for character names** (`_char_names_registry`, `set_char_names`): breaks having two models at once, and tests. "Thread-safe" (docstring) with no lock at all. Pass it as a dependency of the model.
- [ ] **Unused compatibility layer in `text_processing`**: the `CHAR_NAMES` proxy (its `__contains__`/`items`/`keys` copy the dict on every call), `get_char_name(s)`, `_notify_char_names_changed`.
- [ ] **Strong callbacks in `CardData`** (`widgets/card_data.py:38`): every card registers a bound method and depends on someone calling `close()` (today `load_cards` does). `unregister` is `list.remove` (O(n²) when closing thousands). Use `weakref`/a Qt signal, or have the canvas listen once and refresh.
- [ ] **Canvas performance**: `paintEvent` and `card_at` walk **all** cards (`card_layout.py:115`, `card_canvas.py:216`); compute the visible range arithmetically (row = y // height). New `QFontMetrics`/`QFont` per card and per repaint (`card_canvas.py:199-206`, `card_layout._line_h`, `text_area_rect`, `vwf_painter._get_vwf_qfont`); cache them and invalidate on config change. `small = font.__class__(font)` → `QFont(font)`.
- [ ] **`used_bytes` over every section on open** (`_populate_sidebar` → 15 full passes) and twice on every change. Cache per section with incremental invalidation.
- [ ] **`ttf_bytes()` regenerates the font with fontTools** on every `_setup_vwf` (each file load and each VWF change). Cache by (PNG hash, gap, space, pitch).
- [ ] **`p.setClipping(False)`** (`vwf_painter.py:85`, `card_canvas.py:309`) cancels any clip the caller had set; use `p.save()/p.restore()`.
- [ ] **`wheelEvent` ignores `pixelDelta` and doesn't call `event.accept()`** (`card_canvas.py:323`): touchpad scrolling is jumpy. Negative floor division is biased.
- [ ] **Duplicated constants with different values**: `MAX_LINE_CHARS=28`, `WARN_LINE_CHARS=26` (constants) vs `char_limit=28`, `ruler_chars=28`, `warn_chars=24`, `over_chars=26` (config); fixed byte thresholds `>300`/`>150` in the canvas; `VWF_PAGE_LINES` is also used for the monospace-mode bands.
- [ ] **Two sources of truth with `tools/vwf_gen.py`**: `util/vwf_font.py` says "must stay identical". Add a test that compares widths against `vwf_tables.asm`, or share the module.
- [ ] **`vwf_font.py`**: `_load_tiles` assumes a grid (`cell`, `scale`) without validating (ZeroDivision / garbage glyphs with a different PNG); an `overrides` key longer than one character → `ord(k)` raises `TypeError` and disables all of VWF; `dropped_loss` is computed and never shown; `mask` is unused in the editor; the module-level `for _i` loop pollutes the module namespace.
- [ ] **Mixed languages in the UI** (English: Select All, Cut, Open JSON…; Spanish: "Ir a #", "Compilar", "Mesen", messages). Pick one or use `tr()`.
- [ ] **Texts and commands hard-wired to `ff4-en` / `ff4-es`**: `info_lbl` ("make ff4-en", `ui_mainwindow.py:182/372`; with a single-component relative path it reads "cd  && make…"). My `_on_build` hard-codes `make ff4-es`: derive the target from the JSON name (`ff4-es-data.json` → `ff4-es`) and the ROM from `rom/<target>.sfc`.
- [ ] **Build/Mesen buttons** (`ui_mainwindow.py:~114-125, 297-348`): they share `objectName='build_btn'`; `MESEN_NAMES` and the ROM lookup (accepts `.spc`, which is not a ROM) should be configurable; `ui_build_dialog.py` has unused `import os`/`QFont`; `_stop()` blocks the UI thread for up to 1.5 s; there is no keyboard input (it is not a real terminal).
- [ ] **Dialogs without `QDialogButtonBox`**: no visible Cancel button, only Esc/close. "Apply globally" asks for confirmation but "Apply for section" doesn't, and the text "This will override any saved settings for 'X'" is misleading (it doesn't clear overrides). `ThemeDialog`: list-as-holder hack (`self._c_bg=[...]`), no restore-defaults button.
- [ ] **`ViewDialog` lists every font** (`QFontDatabase.families()`), not just monospace ones, and may include the generated VWF font.
- [ ] **Active card text in monospace mode is drawn twice** (canvas + transparent overlay, `card_canvas.py:272-289`); it may look bolder. Check visually.
- [ ] **No packaging**: no `requirements.txt`/`pyproject.toml` (PySide6, pyphen, Pillow, fonttools), no README. Requires Python ≥ 3.10 (`str | None`, `dict[...]`) without saying so. The zip includes `__pycache__` (cpython-313 and 314) and the config with personal settings; add a `.gitignore`.
- [ ] **`main.py`**: docstring with the old workflow (`ff4-en`, `make ff4-en`); `win.verbose` is assigned after construction; `setDesktopFileName("FFIV Script Editor.desktop")` (Qt expects the name without `.desktop`); `sys.path.insert` to run from the repo root (prefer `python -m ff4_editor`).
